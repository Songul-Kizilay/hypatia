# v0.4.x Session Activity Architecture Status

## Purpose

Sprint 4.10 adds a read-only, targeted activity view for a registered
session. It reports the number of eligible conversation records and their
earliest and latest creation times without changing memory, session state, or
persisted files.

## Command Contract

The only recognized command forms are:

```text
session activity
session activity <session-id>
```

Recognition is case-insensitive and explicit. The router does not parse or
validate the suffix. Natural-language lookalikes remain normal conversation.

## Routing Contract

`BrainRouter` recognizes only the explicit `session_activity` intent.
`CognitiveEngine` handles that intent before generic and normal conversation
flows, then coordinates validation, aggregation, and composition.

## Target Resolution

The target is derived only from the command suffix:

```text
session activity <session-id>
→ suffix outer whitespace trimmed
→ inner whitespace preserved
→ case preserved
→ exact, case-sensitive registered-session lookup
```

Request metadata is not used. The request-level session override is ignored,
the persisted active session is ignored, `_resolve_session_id()` is not called,
and `SessionManager.get_active()` is not called.

## Validation and Failure Behavior

```text
session activity
→ Session ID must not be empty.

session activity unknown
→ Unknown session: unknown
```

For either failure, `MemoryManager.all()` and `MemoryManager.search()` are not
called. The failure response has `intent="session_activity"`, `success=False`,
`memory_count=0`, and preserves the request ID.

## Memory Read Flow

For a valid registered target, the complete read flow is:

```text
exact registered-session lookup
→ MemoryManager.all() exactly once
→ brain + conversation tag filter
→ legacy-aware target-session filter
→ count
→ min(created_at)
→ max(created_at)
→ ResponseComposer.session_activity()
```

`MemoryManager.search()` is not used. No `created_at`, alphabetical, content,
or relevance sorting is performed; the aggregation does not depend on the
first or last record returned by `all()`.

## Filtering Rules

Eligible records contain both `brain` and `conversation` tags.

For the `default` target, a missing `metadata["session_id"]` is a legacy match,
and an explicit string value of `"default"` also matches. For a custom target,
only an exactly equal string value matches.

`None`, non-string values, records for another session, and orphan session IDs
are excluded. Missing session metadata does not match a custom target.

## Aggregation Rules

```text
conversation_count = len(filtered_records)

records present:
first_activity = min(created_at)
last_activity = max(created_at)

no records:
first_activity = None
last_activity = None
```

An empty but registered session is therefore a successful result.

## Composer Contract

`ResponseComposer` owns user-visible activity responses through
`session_activity()` and `session_activity_failure()`.

Successful responses use `intent="session_activity"`, `success=True`,
`memory_count=conversation_count`, and the original request ID. Datetimes are
presented with `isoformat()`; absent activity values are shown as literal
`none`.

## Read-Only Guarantees

`session_activity` itself does not write memory, write sessions, change the
active session, change persistence files, or emit new lifecycle or session
events.

`MemoryManager.all()` may retain its existing expiry cleanup and memory-expiry
event behavior. That is inherited memory lifecycle behavior, not a
`session_activity` event.

## Persistence and Restart Behavior

No persistence schema, Bootstrap wiring, or dependency changes are introduced.
`memory.json` and `sessions.json` remain independent schema-v1 documents.

Restart coverage verifies an active `other` session, a target `work research`
session, and conflicting request metadata. Unordered middle/newest/oldest
target records produce count 3 with the true minimum and maximum timestamps.
Wrong-tag, null, non-string, other-session, default, and legacy records are
excluded. The command leaves both JSON documents, schema versions, registry,
active session, memory records, and event list unchanged.

## Out of Scope

- Daily or weekly histograms
- Date-range filtering
- Average content length
- Activity trends
- Cross-session comparison
- Custom result counts
- Topic summaries
- Session rename or deletion
- Mutations
- Schema migrations

## Test Coverage

Unit coverage verifies explicit routing, deterministic presentation, target
validation, exact lookup, metadata and active-state isolation, filtering,
min/max aggregation, and read-only behavior. Bootstrap coverage verifies the
same contract after persistent session and memory restart.

## Completion Statement

Sprint 4.10 provides deterministic, session-targeted activity aggregation
without broadening persistence, lifecycle, or session-state responsibilities.
