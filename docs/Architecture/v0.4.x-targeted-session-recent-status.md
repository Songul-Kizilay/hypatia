# Hypatia v0.4.x Targeted Session Recent History Status

> Stable architectural contract for deterministic, read-only recent history of a command-selected session.

# Purpose

`session recent <session-id>` returns the five newest normal conversation
records for one registered session without changing active session, memory, or
persistence state.

# Command Contract

Only the following explicit forms are recognized:

```text
session recent
session recent <session-id>
```

The complete suffix after `session recent` is the session ID. It is trimmed,
but inner whitespace and case are preserved. Session lookup is case-sensitive.

```text
session recent work research
→ target session ID: work research
```

No count parameter exists in this sprint. The result limit is always five.

An empty suffix returns:

```text
Session ID must not be empty.
```

An unknown ID returns `Unknown session: <id>`.

# Responsibility Boundaries

```text
BrainRouter
→ explicit session-recent recognition only

CognitiveEngine
→ command suffix extraction and validation
→ registered-session lookup
→ record filtering, ordering, and fixed limit

MemoryManager
→ source of active records through all()

ResponseComposer
→ all user-visible session-recent responses
```

# Request Metadata Boundary

`session recent` never calls `_resolve_session_id()`.

`request.metadata["session_id"]` is ignored completely. The target session is
selected only from the command suffix, so metadata cannot override or change
the active session.

# Record Selection Contract

For a validated target session, the engine calls `MemoryManager.all()` once:

```text
all active records
→ tags include brain + conversation
→ missing record session_id becomes default
→ target session equality
→ created_at descending
→ first 5
```

Only missing `session_id` metadata is legacy default-session data. An explicit
`session_id: null`, non-string ID, orphan ID, or different session ID does not
match a normal string target session.

Empty and unknown IDs fail before `MemoryManager.all()` is called.

# Response Contract

```text
Recent conversations in work-1:
1. User: Reviewed the session registry.
2. Hypatia: The persistence contract remains unchanged.
```

Record content is presented unchanged. There is no summarization, rewriting,
trimming, normalization, or content reranking.

`session_recent` has its own results, empty, and failure Composer methods so
that `intent="session_recent"` remains distinct from active-session
`recent_conversations`.

# Lifecycle and Persistence

The command creates no conversation record, persistence write, active-session
change, `brain.*` lifecycle event, or session domain event. Existing expiry
cleanup and expiry events from `MemoryManager.all()` remain inherited memory
lifecycle behavior.

Persistence schemas and Bootstrap wiring remain unchanged:

```text
MemoryRecord unchanged
SessionRecord unchanged
memory.json schema v1 unchanged
sessions.json schema v1 unchanged
Bootstrap wiring unchanged
```

The same filtering, ordering, limit, and read-only behavior is preserved after
Bootstrap restart.

# Deferred Capabilities

- User-provided result counts
- Flag-based count syntax such as `--count`
- Cross-session recent history
- Date filters and pagination
- Semantic retrieval and LLM ranking
- Automatic recall and summaries
- Session rename or deletion

# Completion Statement

Hypatia can deterministically show the five newest normal conversation records
for one explicitly named, persisted session while keeping active-session and
memory state read-only.
