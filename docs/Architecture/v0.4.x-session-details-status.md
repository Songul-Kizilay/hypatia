# Hypatia v0.4.x Session Details Architecture Status

> Stable architectural contract for deterministic, read-only inspection of one registered session.

# Purpose

`session details <session-id>` exposes the persisted state of one registered
session without changing session selection, memory, or persistence state.

# Command Contract

Only these explicit forms are recognized:

```text
session details
session details <session-id>
```

The empty form is routed as a command and returns:

```text
Session ID must not be empty.
```

The command suffix is trimmed, preserves case, and is looked up case-sensitively.
Unknown IDs return `Unknown session: <id>`.

# Responsibility Boundaries

```text
BrainRouter
→ explicit session-details recognition only

CognitiveEngine
→ command ID extraction and validation
→ registered-session lookup
→ target-session conversation aggregation
→ active-state lookup

MemoryManager
→ source of active records through all()

ResponseComposer
→ all user-visible detail and failure responses
```

# Request Metadata Boundary

`session details` never calls `_resolve_session_id()`.

`request.metadata["session_id"]` is ignored completely, including string,
empty, null, unknown, and non-string values. The displayed session is selected
only by the command text.

# Aggregation Contract

For a validated target session, the engine calls `MemoryManager.all()` once:

```text
all active records
→ tags include brain + conversation
→ missing record session_id becomes default
→ target session equality
→ count
```

Only missing `session_id` metadata is legacy default-session data. An explicit
`session_id: null`, non-string ID, or orphan ID is not counted for a normal
string target session.

Empty and unknown session IDs fail before `MemoryManager.all()` is called.

# Response Contract

```text
Session: work-1
Status: active
Conversations: 1 conversation
Created: 2026-08-05T09:10:00+00:00
```

The created timestamp is presented as `session.created_at.isoformat()` without
locale conversion, trimming, or reformatting. Conversation grammar is
deterministic: `0 conversations`, `1 conversation`, and `n conversations`.

Successful responses use `intent="session_details"` and the target count as
`memory_count`. Failures preserve their given message, use the same intent,
and have `memory_count=0`.

# Lifecycle and Persistence

The command creates no conversation record, persistence write, active-session
change, `brain.*` lifecycle event, or session domain event. Existing expiry
cleanup and expiry events from `MemoryManager.all()` remain inherited memory
lifecycle behavior.

Session and memory persistence schemas remain unchanged:

```text
MemoryRecord unchanged
SessionRecord unchanged
memory.json schema v1 unchanged
sessions.json schema v1 unchanged
Bootstrap wiring unchanged
```

The same behavior is preserved after Bootstrap restart.

# Deferred Capabilities

- Session rename or deletion
- Session descriptions
- Last-activity tracking
- Disk usage and memory export
- Conversation listing from this command
- Cross-session aggregation
- Automatic recall or summaries
- Semantic retrieval and LLM integration

# Completion Statement

Hypatia can deterministically inspect a registered session's persisted
identity, active status, creation time, and normal-conversation count while
keeping all memory and session state read-only.
