# v0.4.x Session Rename Plan Status

## Purpose

Sprint 4.12 adds a pure, immutable description of a future session rename.
It adds no command, mutation, persistence write, event, or runtime wiring.

The separate planning step prevents a future multi-document mutation from
mixing decision-making with persistence and runtime state changes.

## Public API

```python
SessionRenamePlanner.create_plan(
    *,
    registered_session_ids,
    active_session_id,
    memory_records,
    source_session_id,
    target_session_id,
) -> SessionRenamePlan
```

`SessionRenamePlan` is immutable (`frozen=True`, `slots=True`) and contains
the source and target IDs, replacement registry order, replacement active ID,
and memory record IDs that a later mutation must update.

The planner accepts plain inputs only. It does not receive or access a
`SessionManager`, `MemoryManager`, store, event bus, or runtime container.

## Validation

Validation is deterministic and uses the existing `SessionError` domain
exception:

```text
source type
→ target type
→ trim both outer boundaries
→ empty source
→ empty target
→ source registry lookup
→ default-source protection
→ source/target equality
→ target duplicate check
```

The corresponding messages are:

```text
Session source ID must be a string.
Session target ID must be a string.
Session source ID cannot be empty.
Session target ID cannot be empty.
Unknown session: <source>
Default session cannot be renamed.
Session source and target must be different.
Session already exists: <target>
```

Lookup and duplicate checks are exact and case-sensitive. A case-only rename,
such as `work` to `Work`, is valid when the target is not already registered.
Outer whitespace is removed; internal whitespace is preserved.

`default` cannot be renamed because legacy records with no `session_id` remain
owned by that session. If `default` is not registered, source lookup fails
first with `Unknown session: default`.

## Planned registry and active-session changes

The plan replaces the source ID in place: registry order is preserved and the
renamed session is never moved. If the source was active, the planned active
ID becomes the target; otherwise it remains unchanged.

## Planned memory migration

The planner selects all memory types that explicitly identify the source:

```python
isinstance(record.metadata.get("session_id"), str)
and record.metadata.get("session_id") == source_session_id
```

No tag filter is used. Missing metadata, `None`, non-string values,
wrong-case values, and whitespace variants are excluded. The selected memory
IDs preserve the supplied record order; there is no sorting or deduplication.

`SessionMemoryPolicy` is deliberately not used here: it describes read-only
conversation ownership, while a future rename must migrate every explicitly
session-bound memory record.

## Purity and compatibility

The plan and its inputs are not mutated. No persistence schema, session
registry, memory record, active state, event sequence, Bootstrap wiring, or
existing command contract changes in this sprint.

`MemoryRecord`, `memory.json` schema version 1, and `sessions.json` schema
version 1 remain unchanged.

## Out of scope

This sprint does not implement session rename execution, transactional writes,
memory metadata migration, rollback or recovery, a Router command, response
text, events, deletion, or session discovery.

## Completion

Sprint 4.12 provides a deterministic, side-effect-free rename plan as the
foundation for a separately designed future rename mutation.
