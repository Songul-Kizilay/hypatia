# v0.4.x Recent Conversation History Architecture Status

> Deterministic, session-aware recent conversation history contract for
> Hypatia after Sprint 4.4.

---

# Purpose

This document records the architectural boundaries and behavioural guarantees
for explicit recent conversation history. It makes active-session conversation
records visible without adding automatic recall, interpretation, or new
persistence formats.

---

# Command Contract

Only these deterministic command forms are recognised:

```text
recent conversations
recent conversations <count>
```

Natural-language phrases that merely mention recent conversations remain
normal conversation.

The default count is `5`. A supplied count must be an integer from `1` to
`20`, inclusive.

```text
non-integer
-> Count must be an integer.

out of range
-> Count must be between 1 and 20.
```

---

# Responsibility Boundaries

## BrainRouter

- Owns only explicit command recognition.
- Does not parse or validate counts.
- Does not resolve sessions or access memory.

## CognitiveEngine

- Owns count parsing and validation.
- Resolves the request session.
- Selects, filters, orders, and limits records.
- Delegates every user-visible response to ResponseComposer.
- Does not write memory, persistence, or session state for this command.

## MemoryManager

- Remains the source of active records through `all()`.
- Retains ownership of expiry cleanup and existing memory lifecycle events.

## ResponseComposer

- Owns all user-visible recent-history list, empty, and failure responses.
- Presents each `record.content` value unchanged.

No persistence schema changes are introduced by this capability.

---

# Record Selection Contract

Recent conversation history always applies selection in this exact order:

```text
MemoryManager.all()
-> tags include brain + conversation
-> resolved session filter
-> created_at descending
-> limit
```

The limit is never applied before tag filtering, session filtering, or
descending creation-time ordering.

Only records whose tags include both `brain` and `conversation` are eligible.
Knowledge-search records, planning records, session commands, and other
internal memory kinds are excluded by this tag contract.

---

# Session Resolution Contract

```text
registered request-level override
-> request-only session

missing / None / blank override
-> active session
```

A request-level override never changes the active session.

Legacy memory records with no `metadata["session_id"]` belong to the `default`
session. Records with an explicit `metadata["session_id"] is None` are not
legacy records and match no normal string session ID.

---

# Response Contract

Recent history is a presentation of stored records, not a generated summary.

```text
record.content is presented unchanged
no summarization
no rewriting
no trimming
no normalization
```

The response only adds the session heading and deterministic record numbering.

---

# Lifecycle and Side Effects

The `recent conversations` command produces no new:

- conversation memory write
- persistence write
- active-session change
- `brain.*` lifecycle event
- session domain event

`MemoryManager.all()` may perform its existing expiry cleanup and may emit
existing memory expiry events. This is inherited memory lifecycle behaviour,
not a recent-conversation-history lifecycle event.

---

# Persistence and Restart Behaviour

Recent history uses the existing persistent memory and session registry
contracts. After Bootstrap reloads both stores, active-session selection,
request-level overrides, record filtering, ordering, and limits retain the
same behaviour.

```text
sessions.json schema version 1
memory.json schema version 1
MemoryRecord unchanged
```

---

# Deferred Capabilities

The following are intentionally outside Sprint 4.4:

- automatic recall
- semantic search
- conversation summaries
- cross-session history
- pagination
- date filters
- text search
- session deletion
- session rename
- side-effect-free memory snapshot API

---

# Completion Statement

Sprint 4.4 adds deterministic, restart-safe access to the most recent normal
conversation records in the resolved session. It extends the existing session
and memory contracts without introducing interpretation, automatic retrieval,
or new lifecycle side effects.
