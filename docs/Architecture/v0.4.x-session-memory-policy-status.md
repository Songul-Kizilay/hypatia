# v0.4.x Session Memory Policy Status

## Purpose

Sprint 4.11 makes the definition of a session-owned normal conversation a
single, read-only policy. It removes duplicated tag and legacy-session checks
without adding a capability or changing persisted data.

## Policy API

```python
SessionMemoryPolicy.is_conversation(record)
SessionMemoryPolicy.belongs_to_session(record, session_id)
SessionMemoryPolicy.matches(record, session_id)
```

`matches(record, session_id)` is exactly the conjunction of conversation
eligibility and session ownership.

## Conversation eligibility

A record is a conversation when its tags include both `brain` and
`conversation`. Extra tags do not alter that decision; missing either required
tag excludes the record.

## Session ownership

For the `default` session, a missing `metadata["session_id"]` is a legacy
match, as is an explicit string value of `"default"`.

For every custom session, ownership requires exact, case-sensitive string
equality. Internal whitespace is preserved. `None` and all non-string values
never match a normal session. An orphan ID matches only if that exact ID is
used as a target; registry filtering remains the responsibility of callers.

## Purity and boundaries

`SessionMemoryPolicy` has no manager, persistence, event, sorting, limit,
aggregation, search, or mutation responsibility. It does not alter records or
metadata.

`CognitiveEngine` continues to choose a target session, obtain records, and
apply each capability's ordering, limit, count, or time aggregation.

## Integrated capabilities

The following read-only flows delegate conversation/session matching to the
policy:

- `session overview`
- `session details <id>`
- `session recent <id>`
- `session search <id> -- <query>`
- `session activity <id>`

## Behavior-preservation guarantees

The refactor does not change response text, active-session behavior, request
metadata rules, or read-only lifecycle boundaries.

- Overview keeps registry order and reads memory once for all counts.
- Details keeps its valid-target one-read and invalid-target no-read behavior.
- Recent keeps newest-first ordering and its five-record limit.
- Search keeps MemoryManager relevance order and applies its five-record limit
  only after filtering.
- Activity keeps count plus minimum and maximum creation times, with no sort or
  limit.

## Persistence and restart behavior

`MemoryRecord`, `SessionRecord`, `memory.json` schema version 1, and
`sessions.json` schema version 1 are unchanged. Bootstrap wiring and runtime
dependencies are unchanged.

Restart regression coverage verifies the shared legacy and exact-ID semantics
across all integrated commands while preserving memory/session document bytes,
registry state, active session, memory records, and domain-event state.

## Out of scope

This sprint does not add session mutations, migrations, new persistence
schemas, new commands, automatic recall, semantic retrieval, or a new memory
query API.

## Completion

Sprint 4.11 centralizes session conversation matching while preserving existing
runtime behavior and persistence contracts.
